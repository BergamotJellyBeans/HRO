# iPhoneからTab5へ時刻・位置を送る

Tab5を更新後、iPhoneの「ショートカット」で以下を一度作成します。
ショートカット名の例：`Tab5 Field Setup`。

## ショートカットの作成

アクション名はiOSのバージョンによって多少異なる場合があります。

1. 「現在地を取得」を追加します。
2. 「場所の詳細を取得」で現在地の「緯度」を取得し、「変数を設定」で `Latitude` に保存します。
3. 同じ現在地から「経度」を取得し、変数 `Longitude` に保存します。
4. 「日付」アクションを追加し、「指定した日付」に `1970-01-01T00:00:00Z` を設定します。変数 `Epoch` に保存します。UTCの1970年1月1日、すなわち日本時間では同日09:00であることを確認してください。
5. もう一つ「日付」アクションを追加して「現在の日付」を取得します。変数 `Now` に保存します。現在地の取得後に行います。
6. 「日付間の時間を取得」で `Epoch` から `Now` までの「秒」を取得します。
7. 「計算」でその秒数に `1000` を掛けます。
8. 「数字を丸める」で小数点以下をなくし、変数 `UnixMs` に保存します。
9. 「URL」に `http://192.168.4.1/api/field` を設定します。
10. 「URLの内容を取得」を追加し、詳細を開いて方法を `POST`、本文を `JSON` にします。
11. JSONの各項目をすべて「数字」で追加します。

| キー | 値 |
| --- | --- |
| version | 1 |
| unix_ms | 変数 UnixMs |
| latitude | 変数 Latitude |
| longitude | 変数 Longitude |

12. 「結果を表示」を追加して、返ってきた結果を表示します。

## フィールドで使う

1. Tab5を起動します。
2. iPhoneを `Tab5-HRO-…` のWi-Fiへ接続します。インターネット接続がないネットワークでも接続を維持します。
3. 作成したショートカットを実行します。位置情報やローカルネットワークの許可が表示されたら許可します。
4. 結果の `status` が `applied`、`clock_updated` が `true` なら適用済みです。`rtc_updated` はRTCへの書き込みと読み戻しの確認結果です。
5. Tab5のコンソールに `Phone time applied (UTC)` と `Field location: … (temporary)` が表示され、上部の緯度・経度が更新されることを確認します。

単体観測の時計表示は `[PHONE]` になります。その後NTP同期に成功すると `[NTP]` に戻ります。ターミナルモードの観測時計は引き続きPi5からのデータを使います。

緯度・経度は今回の起動中だけ使い、config.iniには保存しません。再起動すると設定ファイルの観測位置へ戻ります。RTCに設定した時刻は保持されます。保存された観測地名は変更しません。

位置の取得精度と送信までの遅れはスマートフォンや通信状態によります。時計はスマートフォンのシステム時刻を使用します。観測を始める前に実行すると、観測途中の時刻変更を避けられます。

`http://192.168.4.1/field` には英語の案内ページがあります。家庭内Wi-Fi経由で使う場合はURLのIPアドレスをTab5のSTAアドレスへ変更します。

## 送信形式

POST `/api/field`、Content-Type `application/json`。unix_msはUTC Unix時間のミリ秒です。日付を文字列に整形して送る方式ではありません。

```json
{"version":1,"unix_ms":1791072000000,"latitude":35.44361111,"longitude":133.3458331}
```

上記の時刻は形式説明用です。実際にはショートカットで求めた現在時刻を送ってください。

正常応答例：

```json
{"status":"applied","clock_updated":true,"rtc_updated":true,"config_saved":false}
```

不正な時刻・座標は400、処理できない状態は503、適用待ちのタイムアウトは504です。失敗した場合はTab5の状態を確認して、現在地・現在時刻の取得から再実行します。
